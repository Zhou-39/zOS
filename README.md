## 📌 核心理念

传统AI软件通过API调用实现功能（如读屏），存在天然局限：
- 只能获取当前屏幕静态状态，无法自动翻页或模拟连续操作
- 模拟操作不真实，易触发风控机制
- AI操作本质是"翻译"而非"执行"

**zOS的方案**：将AI嵌入操作系统底层，使其操作即用户操作——直接模拟真实的鼠标、键盘、触控行为，实现自然、安全、抗检测的自动化交互。

## 🎯 训练范式革新

### 问题现状

纯视频训练存在严重安全隐患：
- 模型识别录屏中的鼠标图标和控件，而非真实操作信号
- 可能忽略哈希校验，盲目模仿视频中的操作，导致误执行危险指令

### zOS方案

| 策略 | 说明 |
|------|------|
| **信号来源** | 直接从系统底层获取真实鼠标/点击信号，而非CV识别 |
| **CV角色** | 仅用于总结屏幕内容（如"视频正在播放"），记录位置+哈希（哈希优先） |
| **记忆控制** | 屏幕信息不写入操作记忆，除非用户明确指令："学习视频中的操作并示范" |
| **隐私保护** | 引入**无痕模式**，解决现阶段"真遗忘"技术难题 |


## 🧬 .cell —— 新一代可执行程序格式

> `.cell` 是 zOS 的原生可执行程序格式。它不只是一个文件后缀，而是一套完整的"程序即生命体"哲学体系。

### 为什么是 `.cell`？

- 程序像细胞一样，是**最小功能单元**
- 每个程序有自己的**边界**（细胞膜）、**核心**（细胞核）、**功能器**（细胞器）
- 细胞会**代谢**（更新）、**分裂**（fork/派生）、**凋亡**（优雅退出）
- AI时代，程序应当是有"生命"的，而非静态的二进制尸体


### `.cell` 的本质

`.cell` 本质上是一个**经过私有编码的压缩包**，但**不是简单的 zip/tar**：
- 采用**私有编码协议**（非公开压缩算法 + 自定义元数据结构）
- 内部结构固定、可被官方工具识别
- 普通解压软件无法正确解析，防止随意篡改


### `.cell` 的文件结构

```
myapp.cell/                    ← 私有压缩格式，普通工具不可解析
├── manifest.json              # 细胞"身份证"：元数据、权限声明、入口点
├── nucleus/                   # 细胞核 —— 不可反编译的安全核心
│   └── core.bin               # 私有二进制，仅系统运行时读取
├── organelles/                # 细胞器 —— 功能模块（存储为 .dna）
│   ├── module_a.dna           # 官方中间语言，可读可分析
│   ├── module_b.dna
│   └── module_c.dna
├── membrane/                  # 细胞膜 —— 对外接口声明
│   ├── api.json               # 导出接口定义
│   └── events.json            # 可监听/触发的生命周期事件
├── resources/                 # 资源文件
│   ├── icons/
│   └── locales/
└── dna.manifest               # "遗传信息"：版本链、依赖关系、更新源
```


## 🧬 .dna —— 官方中间语言

> `.dna` 是 zOS 官方推出的中间语言，位于 `.cell` 的 `organelles/` 中。

### 为什么是 `.dna`？

- **生物学隐喻闭环**：细胞（`.cell`）内有 DNA（`.dna`），DNA 携带生命的遗传信息
- **"可读不可逆"的精准隐喻**：DNA 可以被测序、被解读，但**无法从 DNA 还原出完整的生命体**
- **完美对应技术特性**：`.dna` 可读、可分析，但信息量低于原始源码，**天然不可逆回源码**

### 设计目标

| 目标 | 说明 |
|------|------|
| **可读性** | 结构清晰，便于 AI 分析和人工审阅 |
| **不可逆性** | 信息量低于原始源码，天然阻止完整反编译 |
| **安全性** | 类型安全、内存安全，消除常见漏洞类 |
| **AI友好** | 语义清晰，便于 AI 理解"意图"而非"实现" |
| **语言中立** | 不偏向任何原始语言，各语言源码都能有损转为 `.dna` |

### `.dna` 示例（概念）

```
// ============================================================
// 模块：用户认证模块
// 编译自：main.py (原始源码已不可逆)
// DNA 片段 ID：auth_v3.2.1
// 编译指纹：zCORE-9F3A-2B7D
// ============================================================

function authenticate(cred: Credential) -> AuthResult {
    // 验证凭证格式
    validate_format(cred)
    
    // 查询身份源
    identity = lookup(cred.uid)
    
    // 比对密钥（实现细节已抽象）
    match = compare(cred.secret, identity.secret)
    
    return AuthResult {
        success: match,
        user: identity
    }
}

function logout(session: Session) -> Status {
    // 销毁会话
    destroy(session.token)
    
    // 清理缓存
    clear_cache(session.uid)
    
    return Status { code: 200, message: "logged out" }
}
```

### `.dna` 核心特性

| 特性 | 说明 |
|------|------|
| **有损中间表示** | 变量名被抽象化、注释被丢弃、语法糖被展开、格式被规范化 |
| **类型系统** | 强类型，类型安全，带自动内存管理 |
| **无原始痕迹** | 不保留任何原始语言的特定语法或语义 |
| **可读性强** | 类似伪代码的结构化文本，AI 和人都能阅读 |
| **不可执行** | `.dna` 本身不是可执行代码，必须经过 zOS 运行时加载执行 |
| **版本可追溯** | 每个 `.dna` 文件头部包含编译指纹和版本信息 |


### 为什么 `.dna` 无法还原为原始源码？

```
┌─────────────────────────────────────────────────────────────────┐
│                     Python 原始源码                            │
├─────────────────────────────────────────────────────────────────┤
│ def greet_user(name, greeting="Hello"):                       │
│     """向用户打招呼"""                                         │
│     result = f"{greeting}, {name}!"  # 格式化字符串           │
│     print(result)                                             │
│     return result                                             │
├─────────────────────────────────────────────────────────────────┤
│                            │                                   │
│                            ▼                                   │
│              ┌─────────────────────────┐                      │
│              │   Cell Builder 打包过程  │                      │
│              │   (有损信息丢弃)         │                      │
│              └─────────────────────────┘                      │
│                            │                                   │
│                            ▼                                   │
├─────────────────────────────────────────────────────────────────┤
│                      .dna 中间语言                            │
├─────────────────────────────────────────────────────────────────┤
│ function greet_user(input: String, prefix: String) -> String {│
│     output = concat(prefix, ", ", input, "!")                 │
│     print(output)                                             │
│     return output                                             │
│ }                                                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  被丢弃的信息（不可恢复）：                                      │
│  · 原始变量名：name → input, greeting → prefix                │
│  · 注释："""向用户打招呼""" 被移除                             │
│  · 语法糖：f"{greeting}, {name}!" → concat(prefix, ", ", ...) │
│  · 默认参数值：greeting="Hello" → 外部化                      │
│  · 原始缩进/格式 → 被规范化                                    │
│  · Python 特有语义 → 转为通用中间语义                         │
│  · 依赖关系 → 外部化为 manifest.json                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

结论：从 .dna 无法还原出原始 Python 代码——信息已经丢失。
```

## 🧬 核心设计原则

| 原则 | 说明 |
|------|------|
| **细胞膜即边界** | 所有对外交互必须通过 `membrane/` 声明的接口 |
| **细胞核不可解析** | `nucleus/` 中的二进制采用私有编码，无公开反编译能力 |
| **细胞器可学习** | `organelles/` 中的 `.dna` 中间语言可被 AI 解析、分析、审计 |
| **DNA 可读不可逆** | `.dna` 可阅读理解，但信息量低于源码，无法还原原始代码 |
| **单向编译链** | 源码 → `.cell` 是唯一官方方向，不存在 `.cell → 源码` 路径 |
| **私有编码压缩** | `.cell` 使用非公开编码协议，普通解压工具无法解析 |
| **有损转换** | 源码 → `.dna` 过程中变量名、注释、语法糖等被丢弃 |
| **版本可追溯** | 每个 `.cell` / `.dna` 携带编译指纹和版本信息 |


## 🛡️ 知识产权保护矩阵

| 策略层级 | 措施 | 说明 |
|---------|------|------|
| **格式层** | 私有编码压缩 | `.cell` 使用非公开协议，普通工具无法解包 |
| **转换层** | 有损编译 | 源码 → `.dna` 丢弃变量名、注释、语法糖等信息 |
| **结构层** | 核隔离 | `nucleus/` 保持私有二进制，完全不反编译 |
| **工具层** | 单向工具链 | `Builder` 和 `Analyzer` 功能不对称，无"重新打包"路径 |
| **AI层** | 双模型隔离 | 代码生成 AI 与 DNA 解析 AI 为两套独立模型 |
| **升级层** | 官方独占 | `Analyzer` 仅由官方维护升级，无第三方实现 |
| **溯源层** | 水印/指纹 | 每个 `.cell` 植入开发者水印 + 编译指纹 |
| **法律层** | 许可约束 | 官方许可明确禁止 `.dna → 源码` 的逆向工程 |

```
// ============================================================

// 每个 .dna 文件以以下头部开始：

#!dna
version: "1.0"
module: "module_a"

// ---- 类型系统 ----
// 强类型，支持基础类型和复合类型：

类型:
  - 基础: int, float, string, bool, null
  - 复合: array[T], map<K,V>, struct, enum
  - 特殊: Credential, Session, AuthResult (用户自定义)

// ---- 函数定义 ----
// 函数签名 + 逻辑体（实现细节已抽象）

function 函数名(参数列表) -> 返回值类型 {
    逻辑描述
}

// ---- 控制流 ----
// 支持常见的控制流结构，但以"意图描述"为主

if 条件 {
    逻辑块
} else {
    逻辑块
}

for 元素 in 集合 {
    逻辑块
}

// ---- 注意事项 ----
// 1. .dna 不可直接执行，须由 Cell Runtime 加载
// 2. .dna 不包含任何原始语言特有语法
// 3. .dna 不保证与原始源码逻辑完全等价（有损）
// 4. .dna 仅供分析、审计、AI 理解使用
// 5. 严禁从 .dna 还原或补全原始源码
```
